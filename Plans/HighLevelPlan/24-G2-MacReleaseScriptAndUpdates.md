# G2. Mac release script and updates

**Phase G — Replacing site-backups** · Engine, 1–2 sessions, installed build, needs you

References like §2 point to [00-Info.md](00-Info.md). Copy from Locus Git Gui and Locus Launcher: `Scripts/release.sh`, `Scripts/sparkle-tools.sh`, `Scripts/README.md` and `docs/appcast.xml`.

- **One version number for Hive and Beekeeper,** released together, since they share the API
- **`Scripts/release.sh`:** version and build, archives of both Mac apps, Developer ID export, notarizing and stapling (including the bundled rsync, which `Scripts/build-rsync.sh` has to build before archiving, as `install-test-build.sh` does), the appcast, release notes and the GitHub release, printing the publishing commands as the other apps' scripts do
- **Sparkle for Beekeeper on the Mac,** as in the other apps
- **Installing `Hive.app` owned by root** (§4, A2): the daemon refuses to start otherwise, so dragging it from a disk image isn't enough. Most likely a `.pkg` installer, which installs owned by root and asks for an administrator password. Hive's window already tells you when the install isn't owned by root.
- **Hive updating itself** (§19). Each update replaces a root-owned bundle and keeps it root-owned, so it needs an administrator password, for example through Sparkle's installer for apps the user can't write to, or a new `.pkg`. `Hive.app` isn't running most of the time, so decide how, for example: Beekeeper shows "Update available" and opens `Hive.app`, which runs Sparkle and restarts the daemon from the new bundle; or the daemon checks the appcast itself and exits so launchd starts the new version. Record the decision in §2.
- **When Hive and Beekeeper versions differ,** the API version check from B2 tells you which one to update
- **Signing secrets** from the Keychain and environment, never the repository (AGENTS.md). Needs you for the Sparkle key and the notarization profile.
- **Decided (2026-11-11):** a `.pkg` for the first install, Sparkle in `Hive.app` for updates, and GitHub Pages and releases for the feeds and downloads (§2). Sparkle 2.10 keeps the old bundle's owner and group when it installs (`SUPlainInstaller`), and asks for an administrator password when the app isn't writable. The daemon watches its executable and asks for the same graceful restart a new identity uses. Beekeeper reads Hive's version from the overview. `release.sh --rehearsal` builds everything without git checks, notarization or publishing, with appcasts served on 127.0.0.1 that the installed apps can be pointed at through `defaults write <bundle ID> SUFeedURL`, so the whole update can be tried on this Mac first. `Scripts/README.md` has the details and the one-time setup.
- **Rehearsed (2026-11-11):** rehearsal 2026.0.1 installed through Installer from the `.pkg`, owned by root. Beekeeper updated itself to 2026.0.2 through Sparkle and showed "Hive 2026.0.2 is available" with Open Hive. Hive.app's Sparkle installed 2026.0.2 after the administrator password, the bundle stayed root:wheel and writable only by root, the daemon logged the replacement and restarted on the new version as the user within seconds, and Beekeeper reconnected. Sparkle refuses `file://` feeds and downloads, so rehearsals serve `build/rehearsal/` on 127.0.0.1.
- **Released (2026-11-12):** 2026.1, published from `release.sh` and notarized, updated the installed 2026.0.2 rehearsal copies of both apps through Sparkle from the live feed. Hive.app stayed owned by root, the daemon restarted on 2026.1 within seconds, and Beekeeper reconnected. Notarizing reads the team's App Store Connect key from 1Password, as Locus Calendar's release does. Xcode refused to make the Developer ID Installer certificate, taking the account holder for an Admin, so it was made on the developer website.

**Done when:** a release build of both apps updates through Sparkle from the one before; Hive restarts on the new version and Beekeeper reconnects; and the release script stops before publishing, as the other apps' does.
